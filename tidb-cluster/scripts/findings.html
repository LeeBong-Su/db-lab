핵심 발견

  1. 읽기는 노드를 늘려도 지연이 그대로다. 분할 후 point_select 32 스레드에서 단일 11,558 TPS, 3노드 11,652 TPS로 같고 p95도 둘 다 4.49ms다. 리더 하나가 읽기를 처리하는 구조라서 같은 부하에서는 복제본 수가 읽기 지연을 바꾸지 않는다.
  2. 쓰기는 Raft 복제 비용이 그대로 보인다. TiDB 자원을 같게 맞추면(3노드에서 TiDB 1대만 사용) write_only가 759 → 448 TPS(-41%, 32 스레드), 856 → 455 TPS(-47%, 128 스레드)로 떨어진다. p95는 56.8 → 92.4ms다. 커밋마다 과반(2/3) 복제가 끝나야 하고 세 TiKV가 모두 apply하므로 TiKV CPU 합이 2.6 → 5.7코어로 늘었다. 데이터 적재(prepare 100만 행)도 40.2초 → 65.4초(+63%)가 걸렸다.
    주의: 세 TiKV가 같은 WSL 가상 디스크에 fsync하므로 실제 서버 3대보다 쓰기 손해가 과장돼 있다.
  3. 작은 테이블은 리전 1개라 핫스팟이 생긴다. 적재 직후 10개 테이블의 레코드 리전 리더 중 6개가 store1에 몰렸다. 그 결과 TiKV CPU가 2.49 / 1.16 / 1.11코어로 기울었다. PD는 전체 리더 개수를 38/28/29로 맞추지만 부하는 맞추지 못한다. SPLIT TABLE … REGIONS 3와 scatter를 적용하자 1.49 / 1.88 / 1.49로 평탄해지고 TiKV throttling도 사라졌다.
    주의: 같은 시점에 단일 노드도 TPS가 +26% 올랐다. 분할 전 측정이 적재 직후(컴팩션 진행 중)였기 때문에 TPS 개선분을 분할 효과로만 볼 수는 없다.
  4. 3배 자원을 써도 처리량은 크게 늘지 않았다(이 호스트 기준). 128 스레드에서 point_select는 12,564 → 13,417(+7%), read_write는 226 → 285(+26%)였다. 병목은 TiDB CPU 상한(인스턴스당 2코어)이었다. 쿼리 1건당 TiDB CPU는 단일 158us, 3노드 432us로 커졌다. GOMAXPROCS(=2로 정상)와 리전 에러 재시도(수 분 동안 not_leader 약 100건)는 원인이 아닌 것으로 확인했다. 가장 유력한 원인은 호스트 CPU다. Core Ultra 9 185H는 P코어 6개(12스레드)에 E코어 10개가 섞인 구조다. 3노드에서는 바쁜 스레드가 12~15개라 E코어와 HT 형제 스레드까지 쓰게 되고, 그만큼 같은 일에 CPU 시간이 더 든다. 단일 호스트로 시뮬레이션할 때 생기는 한계이고, 실제 서버 3대라면 이 손해는 거의 없다.
  5. 가용성 차이가 가장 결정적이다. 3노드에서 TiKV 1대를 SIGKILL하자 약 14초 동안 처리가 멈췄다가 죽은 노드를 살리지 않은 상태에서 자동으로 회복했다. 이후 2대로 장애 전 처리량의 약 88%(270 → 239 TPS)를 유지했다. PD 리더를 죽였을 때는 약 12초 멈춘 뒤 새 리더가 선출됐다. 두 경우 모두 클라이언트 에러는 0건이었다(TiDB가 backoff하며 재시도). 단일 노드는 TiKV가 죽어 있는 약 25초 내내 TPS가 0이었고 재기동한 뒤에야 회복했다. 장애 구간 p95는 3노드 15초, 단일 27초까지 치솟았다.
  6. 운영 포인트: 복구된 노드에는 리더가 바로 돌아오지 않는다. 장애 노드를 재기동하고 30초가 지나도 리더 수는 79 / 69 / 7이었다. 계획 정비라면 tiup cluster restart -N처럼 evict-leader를 거치는 경로를 써야 리더를 미리 옮겨 두고 끊김 없이 작업할 수 있다.

측정 조건과 한계

  • 모든 노드가 한 대의 WSL2(22 vCPU / 31GB)를 공유한다. CPU 상한은 systemd CPUQuota(CFS)로 걸었고, 디스크·메모리 대역폭·물리 코어는 공유된다.
  • 데이터는 sysbench 10 × 10만 행(약 230MB)이라 전부 block cache에 들어가는 메모리 워크로드다. 디스크 I/O 특성은 거의 반영되지 않는다.
  • 워크로드마다 45~60초씩 1회만 측정했다. ±10% 안팎의 차이는 오차일 수 있다.
